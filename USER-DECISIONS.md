# Зафиксированные решения владельца

Дата фиксации: **26 июля 2026 года**. Эти решения считаются окончательными для первой версии. Реализатор не должен повторно спрашивать их у владельца.

## Платформа и доступ

- Hermes Agent работает 24/7 на VPS с Ubuntu 24.04.
- На bootstrap агент получает полный терминальный доступ и временный `sudo/root`.
- После bootstrap все постоянные процессы работают от отдельного непривилегированного пользователя `hermesfactory`.
- Нужно установить и настроить Docker, Hermes Agent, GitHub CLI, Codex, firewall, systemd, резервное копирование, мониторинг и всё необходимое.
- Hermes подключается к ChatGPT Pro/Codex Work, Nous Portal, DeepSeek и Kimi только в рамках уже имеющихся подписок/доступа.
- Платный API и автоматическая покупка кредитов запрещены.

## Бюджет и модели

- Основной ресурсный лимит - квоты, кредиты и rate limits подписок, а не денежный API-бюджет.
- Система обязана минимизировать число модельных вызовов, длину контекста и повторную обработку.
- Разрешена передача несекретных данных любому провайдеру, подключённому через Hermes.
- Секреты, токены, production-дампы и персональные данные не передаются модели без отдельной политики продукта.

## Поддерживаемые продукты v1

- web-приложения;
- REST/HTTP API;
- Telegram-боты;
- CLI;
- автоматизация данных;
- LLM-приложения.

Desktop, mobile и финансовые системы подключаются позднее отдельными profiles/policy packs.

## Риск

Высокорисковые направления не запрещены полностью. Торговля реальными деньгами, платежи, персональные данные, медицина, юридически значимые действия, security tooling и управление production включаются только отдельным Product Contract, усиленными gates, staging и специальной deployment policy.

## Значения продукта по умолчанию

- пользовательский интерфейс: русский;
- код, API, имена файлов и технические идентификаторы: английский;
- внутреннее время: UTC;
- отображение: локальный часовой пояс пользователя;
- персональные данные: отсутствуют до явного включения;
- backend: Python 3.12+ / FastAPI как предпочтение;
- web: TypeScript / React или Next.js;
- постоянные данные: PostgreSQL;
- небольшое развёртывание: Docker Compose;
- отклонение от стека: только через ADR.

## Автоматическое развёртывание

- низкий и средний риск: staging и production автоматически после всех gates;
- высокий риск: staging автоматически, production только по специальной policy, где заранее определены условия;
- административный интерфейс Hermes: только localhost + VPN или SSH-туннель;
- пользовательские продукты: отдельные HTTPS-домены.

## GitHub

- фабрика: `brullik/hermes-software-factory`;
- предпочтительная видимость фабрики: public, без секретов и production-данных;
- новый продукт: отдельный repository;
- безопасный продукт по умолчанию: public;
- продукт с персональными/конфиденциальными данными, реальными финансами, платежами, медициной, юридическими действиями или закрытыми интеграциями: принудительно private;
- public repository не используется как механизм увеличения квот модели;
- ветка `main` защищена; direct push и force push запрещены;
- PR создаются, проверяются и squash-merge выполняется автоматически.

## Инфраструктура

- текущий VPS используется как control plane, staging и для низкорисковых production-продуктов;
- один активный продукт;
- не более двух Builder одновременно;
- одна операция deployment;
- следующий VPS приобретается только при реальной необходимости через `OWNER_ACTION`;
- высокорисковый production должен быть вынесен на отдельный VPS.

## Telegram

- один владелец по allowlist Telegram user ID;
- публичные группы запрещены;
- бот принимает идеи, показывает статус, pause/resume/cancel и OWNER_ACTION;
- секрет Telegram не хранится в Git и не выводится в отчёты.

## Секреты и backup

Принята экспертная схема:

- GitHub Actions/Environment Secrets - только для CI/CD;
- credentials VPS - root-owned файлы `0600` либо systemd credentials;
- runtime secrets - Docker secrets/read-only mounts, не environment dump;
- encrypted backup - restic;
- для stateful production обязателен offsite backend;
- если offsite-хранилище ещё не подключено, staging разрешён, а production с постоянными данными блокируется одним `OWNER_ACTION`.

## Пилот

Система сама сканирует существующие репозитории владельца и выбирает безопасный проект, наиболее близкий к:

- React UI;
- REST API;
- PostgreSQL;
- Telegram notifications;
- authentication;
- tests;
- CI;
- staging;
- monitoring;
- rollback.

Финансовые, торговые и иные высокорисковые репозитории исключаются. Если подходящего репозитория нет, система создаёт `brullik/hermes-factory-pilot`.

## Политики П1-П22

Все предложенные владельцу политики П1-П22 приняты со следующими уточнениями:

- Product Director может задать уточняющий вопрос, но отсутствие ответа не блокирует обратимые решения.
- Необязательные новые функции Product Tester помещает в backlog.
- Полные агентские транскрипты хранятся 14 дней, аудит 90 дней.
- Создаваемый public repository не получает open-source лицензию автоматически: юридический выбор лицензии является отдельным решением Product Contract.
